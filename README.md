# 一种基于多源账号内容的 CC98 回帖检索与分析系统

## 摘要

校内论坛在学术与生活信息流通中扮演着重要角色，但在多账号场景下，用户历史回帖分散、上下文丢失、跨账号检索困难等问题较为突出。本文提出并实现了一种“本地优先、端侧加密、跨账号聚合”的 CC98 回帖检索与分析系统：以浏览器 IndexedDB 为持久层，结合主密码派生密钥对数据透明加密；在 UI 上提供“概览、搜索、统计、配置”四个视图的一致布局与交互；支持按账号或全局范围聚合浏览、轻量全文检索、发帖热力图与小时分布分析；并通过可见的进度浮层展示同步状态，同时提供“强制同步（覆盖本地）”与“主密码重置（清空并重建金库）”。实验表明，该系统能在隐私可控的前提下显著提升跨账号历史回帖的可达性与可用性。主要贡献包括：1）端侧加密的 IndexedDB 存储与仓库封装；2）与账号切换一致的检索/统计范围模型；3）可解释的同步进度与强制同步机制；4）实用的时序可视化组件。

## 引言

CC98 作为浙江大学长期运行的校内论坛，承载了大量课程学习、科研讨论与校园生活信息。然而，用户在长期使用中普遍面临三类问题：其一，回帖检索与上下文定位困难——论坛回复页不展示主题楼层标题，时间一久难以回忆当时讨论的是什么；其二，多账号协同与历史统一管理缺失——用户可能基于场景分设账号，但官方仅支持单一会话登录，跨账号检索、对比与收藏并不便捷；其三，缺乏面向个人历史行为的数据分析与可视化——很难从年度、小时等维度反思自己的发帖活跃度和兴趣领域。现有功能难以满足“多源聚合、隐私友好、可视分析”的复合需求。

本文工作针对上述痛点，设计并实现了一个“浏览器本地运行、数据加密存储、跨账号统一视图”的回帖检索系统。在不依赖后端私有服务的前提下，系统通过端侧加密与本地索引实现数据控制与低延迟检索；通过一致化的界面与导航降低跨页操作成本；并通过发帖时间热力图与小时分布提供基础的行为分析能力。

## 背景

CC98 的基本交互围绕“主题-回复-版面”展开。面向个人视角的“我的回复”在官方界面上以时间为主线，但对“主题上下文、跨账号整合、历史趋势”支持有限。另一方面，浏览器端的 IndexedDB 提供了较大的容量与较好的读写性能，适合做端侧缓存与本地索引；结合 WebCrypto 派生密钥，可以实现“主密码驱动的透明加密”，在不泄露明文的前提下进行本地计算。受限于论坛频率限制与会话机制，端侧同步需要处理令牌获取、请求串行与节流等工程问题。

## 动机

以“插眼（缩写 cy）”为例，用户往往需要在事后回看自己的回复，并跟进楼内后续变化。但官方页面缺乏对“主题标题与楼层上下文”的便捷回溯，跨账号线索更难统一。我们希望以“本地聚合 + 轻量索引”的方式重建个人历史的可达性：在端侧汇集多个账号的回帖，支持全局或按账号过滤，并提供快速检索与可视化概览，使“找回当时的那条回复”这类任务从分钟级降到秒级。

## 设计

- 隐私与威胁模型
	- 主密码仅用于派生密钥，不持久化；派生所用盐以安全基元存储于 `localStorage`（仅为派生可复现，不泄露明文）。
	- 通过加密存储（CryptoStorage/KeyManager）封装对 IndexedDB 的透明加解密，覆盖账户凭证引用、帖子与配置等数据域。
	- 提供“金库重置”：清空加密仓库、重建盐与密钥，避免历史密钥泄露风险。

- 架构与模块
	- 前端：Vue 3 组合式 API + Pinia 状态管理 + PrimeVue 组件库；Vite 构建，Tailwind 用于样式原子化。
	- 数据层：加密仓库包裹 IndexedDB，按域拆分：帖子仓库、账号仓库、配置仓库；会话令牌仅在内存中缓存。
	- 服务层：Forum API 客户端（带最小 2 秒请求间隔的顺序队列），SearchIndex，ServiceContext 注入。
	- 视图与状态：
		- 概览（Overview）：跨账号聚合时间线，提供“同步/强制同步”与进度浮层；
		- 搜索（Search）：与账号选择器同一范围模型，统一布局与结果卡片；
		- 统计（Stats）：年内发帖热力图（周×小时）、24 小时分布、热门版面 Top5；
		- 配置（Settings）：粘性侧边导航与快捷跳转，索引清理与账户管理。

- 同步与范围模型
	- 基于账号粒度同步；选择“全部账号”时按已加载账号做本地聚合，无需额外远端合并。
	- 强制同步会清空该账号本地缓存与索引，再以远端为准重建；普通同步做增量拉取与合并。
	- 进度浮层可见性与语义：启动时可见、按“处理条目数”推进、保证最小可见时长、在“已最新/无可同步”时也给出明确提示。

- 检索与可视化
	- 每账号维护轻量本地全文索引，并支持“全部账号”聚合查询；
	- 可视化以“时间密度”为核心：年度热力图用于宏观概览，小时分布用于日内节律观察，热门版面用于兴趣领域复盘。

## 实现

- 加密与持久化
	- `KeyManager`：从主密码与盐派生密钥，提供 lock/unlock；
	- `CryptoStorage`：序列化密文载荷与解密；
	- 加密仓库：帖子/账号/配置 Repository 统一封装 IndexedDB 读写与迁移；提供 `clear()` 与 `saveMany()` 等 API。

- 会话与令牌
	- `sessionStore` 负责主密码解锁、令牌缓存与账户激活；登录凭证仅保存在内存，错误时自动清理。
	- 提供“主密码重置（resetVault）”，一键清空仓库并重建密钥派生环境。

- 同步与节流
	- `postStore.sync(accountId, { force })`：
		- 普通同步基于游标做增量；强制同步先清空本地再全量拉取；
		- 使用顺序请求队列与最小时间间隔（2s）避免触发风控；
		- 以“条目数”为进度总量，页面消费时累进；在“已是最新/无可同步”场景下也会完成进度并更新文案。

- 进度浮层
	- `progressStore`：`start(total,label)`、`updateTotal(n)`、`step(k)`、`setLabel(text)`、`finish()`；
	- 最小可见时长以避免“闪一下”的体验；支持中途调整总量与标签（如“写入本地缓存…”）。

- 检索与统计
	- 统计页实现年内热力图（周×24 小时）与小时分布条，热门版面 Top5；
	- 组件采用 PrimeVue 的 Card/Chip/Tag 等实现一致化视觉风格。

## 评估

为评价系统的可用性与性能，建议从以下维度测量：

- 同步性能：
	- 首次全量同步时间（每 1000 条帖子，秒）；
	- 增量同步时间与网络调用次数；
	- 强制同步的重建耗时。
- 检索性能：
	- 索引构建时间（每 1000 条）；
	- 查询端到端延迟 P50/P95（毫秒）；
- 正确性：
	- 远端与本地条目数一致率、重复合并率；
- 交互体验：
	- 进度浮层可见性与语义准确率（是否覆盖“已最新/无新增”等场景）；
	- 首屏渲染与滚动流畅度（FPS）。

上述指标可结合浏览器 Performance 面板与埋点日志进行采集；在不同网络状况下（校园网/移动网络）做对比更具参考价值。

## 讨论

- 端侧加密与索引的权衡：密文落地保障隐私，但会增加序列化与解密开销；对大规模数据需在批量粒度与缓存复用上进一步优化。
- API 频控与同步策略：顺序队列与最小间隔能降低被限风险，但也拉长全量同步时间；未来可考虑条件请求与差量摘要。
- 范围统一与一致性：将“账号范围”作为全局一等公民可降低心智负担，但也要求各页严格遵循该约束并处理“全部账号”的多源聚合边界情形。

## 不足与未来展望

- 主题上下文：概览列表仍以版面名为主，后续可补充“主题标题与摘要提取”，提升回溯效率。
- 多端一致性：当前为单浏览器实例本地金库存储；可探索基于端到端加密的云备份与多端同步。
- 更丰富的分析：按版面/主题的长期兴趣曲线、关键词演化、交互网络等。
- 异常与恢复：断点续传、失败重试、并发多标签页的同步协调。
- 可访问性与移动端：完善键盘操作、暗色主题与 PWA 支持。

## 总结

本文实现了一个“本地优先、端侧加密、跨账号聚合”的 CC98 回帖检索与分析系统，在隐私可控的前提下提升了个人历史回帖的可达性与分析能力。系统在范围统一、进度可见、强制同步与主密码重置等方面提供了可解释、可操作的工程方案，为类似校内社区工具的端侧实现提供了参考。
